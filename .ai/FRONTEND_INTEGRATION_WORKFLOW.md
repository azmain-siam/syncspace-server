# Frontend API Integration: Collaboration Workflow

This document defines the exact working agreement and step-by-step process between the **User** and the **AI Assistant** for integrating the SyncSpace backend APIs into the frontend application.

---

## 🎯 Purpose & Goal

To integrate all backend APIs into the frontend cleanly, module by module, using an external **Frontend AI Agent**, without confusion, missing types, or context overload.

---

## 🔄 The Step-by-Step Working Process

```text
  [ User ]                                           [ Assistant ]
     │                                                     │
     │ 1. "Give me a module to integrate"                 │
     ├────────────────────────────────────────────────────>│
     │                                                     │ 2. Selects the next logical
     │                                                     │    module in dependency order
     │                                                     │
     │                                                     │ 3. Writes complete specs
     │                                                     │    into a dedicated doc
     │                                                     │
     │ 4. "Module [X] is ready in [.ai/...]"               │
     │<────────────────────────────────────────────────────┤
     │                                                     │
     │ 5. User copies/hands doc to Frontend AI Agent       │
     │ 6. Frontend AI Agent integrates API & UI            │
     │                                                     │
     │ 7. "Give me the next module"                        │
     ├────────────────────────────────────────────────────>│
     │                                                     │ (Repeats until complete)
```

### 1. User Prompts for a Module
- You ask: *"Give me the next module to integrate"* (or request a specific one).

### 2. Assistant Chooses the Module
- The assistant picks the next module based on natural dependency order (e.g., Auth must come before User Profile, Workspace must come before Projects, Projects must come before Tasks).

### 3. Assistant Generates the Module Documentation
- The assistant writes a comprehensive, self-contained documentation file for that specific module.
- Every module doc will contain:
  - **Endpoints**: HTTP Method, URL path, required headers, and role permissions.
  - **Request Body / Params**: Complete TypeScript interfaces, required vs. optional fields, and validation rules.
  - **Response Body**: Exact normalized response envelope (`{ success, statusCode, message, data }`) with fully typed `data`.
  - **Errors & Status Codes**: Expected error responses (400, 401, 403, 404, 409) with error payload structures.
  - **Real-Time Events**: Any Socket.IO events related to the module (if applicable).
  - **Frontend Tips**: Recommended query keys, cache invalidation rules, and token handling.

### 4. User Gathers & Hands Off to Frontend AI Agent
- You take the documentation generated by the assistant and feed it directly to your frontend AI agent.

### 5. Repeat
- Once that module is integrated on the frontend, you ask for the next module, and the cycle continues until the entire app is connected.

---

## 📋 Recommended Module Order

1. **Authentication & Security** (`/auth/*`)
2. **Current User Profile** (`/user/*`)
3. **Workspaces & Members** (`/workspaces/*`)
4. **Projects & Views** (`/projects/*`)
5. **Kanban Boards & Columns** (`/boards/*`, `/columns/*`)
6. **Tasks, Checklists & Links** (`/tasks/*`, `/checklists/*`, `/links/*`, `/attachments/*`)
7. **Comments & Emoji Reactions** (`/comments/*`)
8. **Agile Sprints & Backlog Triage** (`/sprints/*`, `/backlog/*`)
9. **Real-Time WebSockets** (`/realtime` gateway, presence, room events)
10. **In-App Notifications** (`/notifications/*`)
11. **Data Safety & Feeds** (`/trash/*`, `/activities/*`, `/audit-logs/*`)
12. **Global Search & Dashboard Analytics** (`/search/*`, `/dashboard/*`)

---

## 🤖 Assistant Commitments

- **Zero Guesswork**: Always provide exact field names, enums, and types as implemented in the NestJS backend.
- **Self-Contained Specs**: Provide everything the frontend agent needs in the document so it never has to guess response structures.
- **One Module at a Time**: Keep each step laser-focused to maintain high implementation quality.
