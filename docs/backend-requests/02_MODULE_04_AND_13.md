# Backend Clarifications & Specifications: Module 04 & Module 13

> **Status**: Official Backend Architectural Clarifications  
> **Target Audience**: Frontend Engineers / Frontend AI Agent  
> **Base URL**: `/api/v1`  
> **Auth**: `Authorization: Bearer <accessToken>`

---

## 🎯 Executive Summary of Answers

| Item | Topic | Specification |
| :--- | :--- | :--- |
| **1** | **Route Prefix** | Project routes are **`/api/v1/workspaces/:workspaceId/projects`**. Archive supports both `PATCH .../archive` and `PATCH ...` with `{ "status": "ARCHIVED" }`. |
| **2** | **Task Status Enum** | Globally **`REVIEW`** (`TODO`, `IN_PROGRESS`, `REVIEW`, `DONE`). No `IN_REVIEW`. |
| **3 & 4** | **Analytics Endpoints** | **ALL 6 ENDPOINTS ARE ACTIVE**. None were removed: `/summary`, `/task-distribution`, `/productivity` (time-series), `/sprint-health`, `/project-rollups`, `/member-workload`. |
| **5** | **Drill-down Filters** | Use `?dueDate=today\|overdue\|this_week\|upcoming\|nodate` and `?assigneeId=me\|unassigned\|<uuid>`. |
| **6** | **Task Permissions** | **Present on every task** in `getWorkspaceTasks` via `task.permissions: { canEdit, canDelete, canAssign }`. |
| **7** | **Avatar Field** | Globally **`avatar`** (`string | null`). Not `avatarUrl`. |
| **8** | **Guest RBAC** | Dashboard analytics (`/dashboard/*`) **blocks Guests (403)**. Task query (`/tasks`) **allows Guests** but automatically filters to their projects. |
| **9** | **Grouped Pagination** | **Global page-based**. `meta` is workspace-wide, `groups` partitions the page's items into buckets with `tasksCount` and `hasMore`. |
| **10** | **Project Fields & `_count`** | `_count: { projectMembers, boards, sprints, links }`. `key`, `slug`, `color` are DB nullable for legacy rows but always generated by backend on creation. |

## 1. Route Prefix & Actions (Module 04)

### 1.1 Canonical URLs
All project routes are nested under the workspace:

```text
POST   /api/v1/workspaces/:workspaceId/projects                     -> Create Project
GET    /api/v1/workspaces/:workspaceId/projects                     -> List Workspace Projects
GET    /api/v1/workspaces/:workspaceId/projects/:projectId          -> Get Project by UUID or Slug
PATCH  /api/v1/workspaces/:workspaceId/projects/:projectId          -> Update Project
DELETE /api/v1/workspaces/:workspaceId/projects/:projectId          -> Soft Delete Project
PATCH  /api/v1/workspaces/:workspaceId/projects/:projectId/restore  -> Restore Soft-Deleted Project
PATCH  /api/v1/workspaces/:workspaceId/projects/:projectId/archive  -> Archive Project
GET    /api/v1/workspaces/:workspaceId/projects/:projectId/tasks    -> Get Project Tasks (flat list)
```

### 1.2 Sub-resource URLs
```text
POST   /api/v1/workspaces/:workspaceId/projects/:projectId/links             -> Add Link
GET    /api/v1/workspaces/:workspaceId/projects/:projectId/links             -> List Links
DELETE /api/v1/workspaces/:workspaceId/projects/:projectId/links/:linkId     -> Delete Link

POST   /api/v1/workspaces/:workspaceId/projects/:projectId/status-updates    -> Post Status Update
GET    /api/v1/workspaces/:workspaceId/projects/:projectId/status-updates    -> List Status Updates
```

### 1.3 Archiving Behavior
Frontend can use **either**:
- **Dedicated route**: `PATCH /api/v1/workspaces/:workspaceId/projects/:projectId/archive` (Workspace Owner)
- **General update route**: `PATCH /api/v1/workspaces/:workspaceId/projects/:projectId` with body `{"status": "ARCHIVED"}` (Workspace Owner or Admin).

## 2. Task Status Enum (Global)

The Prisma database schema and TypeScript enum is:

```typescript
export enum TaskStatus {
  TODO = 'TODO',
  IN_PROGRESS = 'IN_PROGRESS',
  REVIEW = 'REVIEW',
  DONE = 'DONE',
}
```

- **`REVIEW` is the global enum value everywhere** across Kanban columns, sprints, task queries, my-tasks, and dashboard metrics.
- `IN_REVIEW` was an accidental cosmetic draft typo in early docs. **Do not use `IN_REVIEW` and do not write mappers.**

## 5. Drill-Down Filters (Workspace Task Explorer)

Endpoint: `GET /api/v1/workspaces/:workspaceId/tasks`

### 5.1 Date Filters via `dueDate` param:
- `?dueDate=today` -> Tasks due today between `00:00:00` and `23:59:59`
- `?dueDate=overdue` -> Tasks where `dueDate < startOfToday` and `status != DONE`
- `?dueDate=this_week` -> Tasks due within the next 7 days
- `?dueDate=upcoming` -> Tasks due after today
- `?dueDate=nodate` (or `no_due_date`) -> Tasks with no due date set (`dueDate === null`)

### 5.2 Assignee Filters via `assigneeId` param:
- `?assigneeId=me` -> Resolves dynamically to the authenticated caller's UUID
- `?assigneeId=unassigned` (or `none`) -> Tasks with `assigneeId === null`
- `?assigneeId=<uuid>` -> Specific user
- `?assigneeId=<uuid1>,<uuid2>` -> Comma-separated list of assignees

### 5.3 Additional Filters:
- `status`: e.g. `?status=IN_PROGRESS,REVIEW`
- `priority`: e.g. `?priority=HIGH,URGENT`
- `projectId`: e.g. `?projectId=<uuid>`
- `sprintId`: e.g. `?sprintId=<uuid>` or `?sprintId=none`
- `isBacklog`: `?isBacklog=true` or `?isBacklog=false`
- `search`: Full text search on `title`, `description`, or `key` (e.g. `?search=auth`)
- `sortBy`: `'dueDate' | 'priority' | 'status' | 'createdAt' | 'updatedAt' | 'title' | 'order'`
- `sortOrder`: `'asc' | 'desc'`
- `groupBy`: `'none' | 'project' | 'priority' | 'status' | 'dueDate' | 'assignee'`

## 6. Task Permissions Model

Every task item in `getWorkspaceTasks` includes a fully populated `permissions` object:

```typescript
export interface WorkspaceTaskItem {
  id: string;
  key: string;
  title: string;
  status: TaskStatus;
  priority: TaskPriority;
  dueDate: string | null;
  // ... other fields
  permissions: {
    canEdit: boolean;   // true if Owner/Admin/Member or task creator/assignee
    canDelete: boolean; // true if Owner/Admin or task creator
    canAssign: boolean; // true if Owner/Admin/Member or task creator
  };
}
```

The drill-down sheet is **not read-only**. Use `task.permissions` to gate editing actions in the UI.

## 8. Role-Based Access Control (RBAC)

### 8.1 Dashboard Analytics (`/workspaces/:workspaceId/dashboard/*`)
- Allowed: `OWNER`, `ADMIN`, `MEMBER`.
- **`GUEST` users receive HTTP 403 Forbidden (`"Insufficient permissions"`)**.

### 8.2 Workspace Task Query (`/workspaces/:workspaceId/tasks`)
- Allowed: `OWNER`, `ADMIN`, `MEMBER`, and `GUEST`.
- **Automatic Scoping for Guests**: If caller is `GUEST`, the backend query automatically adds:
  `project: { projectMembers: { some: { userId: currentUser.id } } }`.
  Guests can only see tasks from projects they belong to.

## 9. Grouped Tasks Pagination Model

When calling `GET /workspaces/:workspaceId/tasks?groupBy=status&page=1&limit=20`:
1. **Global Pagination**: The database applies `skip: (page - 1) * limit` and `take: limit` across all workspace tasks.
2. **Partitioning**: The returned page of tasks is partitioned into the `groups` array:
```typescript
{
  "tasks": [ ...20 items... ],
  "groupedBy": "status",
  "groups": [
    {
      "key": "IN_PROGRESS",
      "label": "IN_PROGRESS",
      "tasksCount": 8,
      "hasMore": false,
      "tasks": [ ...8 items... ]
    },
    {
      "key": "TODO",
      "label": "TODO",
      "tasksCount": 12,
      "hasMore": false,
      "tasks": [ ...12 items... ]
    }
  ],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 48,
    "totalPages": 3,
    "hasNextPage": true,
    "hasPreviousPage": false
  }
}
```
- Paging controls increment `page` to load subsequent workspace batches.

## 10. Project List `_count` & Field Nullability

### 10.1 `_count`
In `GET /workspaces/:workspaceId/projects`:
```typescript
_count: {
  projectMembers: number;
  boards: number;
  sprints: number;
  links: number;
}
```

### 10.2 Field Nullability
- `key`, `slug`, and `color` are defined as nullable in Prisma for legacy schema safety, but **backend logic guarantees they are generated and populated on creation**:
  - `key`: Auto-generated from title or prefix if omitted.
  - `slug`: Auto-slugified from title if omitted.
  - `color`: Defaults to `'#3B82F6'` if omitted.
- **Frontend recommended typing**:
```typescript
export interface ProjectSummary {
  id: string;
  workspaceId: string;
  title: string;
  key: string;       // fallback: project.key ?? 'PROJ'
  slug: string;      // fallback: project.slug ?? project.id
  color: string;     // fallback: project.color ?? '#3B82F6'
  icon: string | null;
  brief: string | null;
  description: string | null;
  visibility: ProjectVisibility;
  priority: ProjectPriority;
  health: ProjectHealth;
  status: ProjectStatus;
  leadId: string | null;
  lead: UserMinimal | null;
  createdById: string;
  createdBy: UserMinimal;
  startDate: string | null;
  dueDate: string | null;
  repoUrl: string | null;
  metadata: Record<string, unknown> | null;
  createdAt: string;
  updatedAt: string;
  _count: {
    projectMembers: number;
    boards: number;
    sprints: number;
    links: number;
  };
}
```
